# Kilo模型工具箱

在 VS Code 中集中管理 Kilo Code 的供应商、自定义模型和推理选项，并提供模型分组调整与原生保存修复。

## 功能

- **供应商管理**：添加、编辑供应商名称、API 地址、协议和 API Key，支持 OpenAI 兼容、OpenAI 与 Anthropic。
- **模型管理**：读取供应商模型列表，搜索、批量勾选并导入；也可以手动添加、编辑或删除模型，设置显示名称和图片能力。
- **推理配置**：设置推理强度档位，或配置“默认／关闭”思考模式；支持协议模板和自定义 JSON 参数。
- **模型分组与界面修复**：隐藏 Kilo Gateway 模型、取消“最常用”分组，修复受支持版本的原生模型保存和默认推理选项显示。
- **保存与恢复**：模型修改前提供预览；每次写入配置先备份，检测外部修改以避免覆盖，并可恢复完整配置。

## 安装与打开

1. 安装 VS Code（1.90 或更新版本）和 Kilo Code，准备好 Kilo 配置文件。
2. 从 [Releases](https://github.com/Siyin22/kilo-model-toolbox/releases/latest) 下载 `.vsix` 安装包。
3. 打开 VS Code 扩展面板，点击右上角菜单，选择 **从 VSIX 安装…**，选中下载的文件。
4. 按 `Ctrl+Shift+P`，运行 **Kilo模型工具箱**。

使用安装包不需要额外安装 Node.js 或 Python。读取供应商模型列表需要系统提供 `curl`（Windows 10/11 通常自带）。

工具箱默认读取 `~/.config/kilo/kilo.jsonc`，不存在时读取同目录的 `kilo.json`；Windows 下 `~` 指用户主目录。如果提示找不到配置，请在 VS Code 设置中搜索 `kiloModelManager.configPath`，填写已有配置文件的绝对路径，然后重新打开工具箱。

## 配置供应商与模型

### 1. 添加或选择供应商

左侧供应商下拉框下方提供 **＋ 添加**、**编辑**、**读取模型** 三个操作。

点击 **＋ 添加**，填写供应商 ID、显示名称、API 协议、API 地址和 API Key，再点击 **保存供应商** 并确认。API 地址应包含供应商要求的版本路径，例如 `https://api.example.com/v1`。

已有供应商可直接在下拉框中选择，再点击 **编辑**。供应商 ID 不可修改；API Key 留空会保留已有凭据，也支持填写 `{env:变量名}` 引用环境变量。已有密钥不会显示在编辑页面。

### 2. 导入或手动添加模型

**从供应商读取：**

1. 选择供应商，点击 **读取模型**。
2. 搜索并勾选需要的模型，也可使用 **全选搜索结果**。
3. 点击 **导入所选模型**，在弹窗中确认。

导入只添加尚不存在的模型，不覆盖已有模型配置。模型列表通常不包含可靠的能力信息，导入后请按实际情况设置推理与图片支持。

**手动添加：** 点击 **＋ 添加模型**，填写准确的模型 ID 和显示名称，再配置能力与推理选项。左侧支持按 ID 或名称查找模型。

### 3. 编辑、保存与删除

选中模型后，在右侧编辑显示名称、推理能力、图片支持和推理参数。核对 **修改预览**，点击 **确认并保存**，再确认弹窗。

已有模型的 ID 为只读；需要更换 ID 时，请添加新模型，再删除旧模型。删除入口在模型编辑表单底部，也需要确认。

如果要放弃编辑，点击状态区的 **清空未保存修改**；需要重新读取配置时点击顶部 **刷新**。保存后若 Kilo 未更新，点击 **重新加载窗口**，这会重启当前窗口中的扩展。

## 设置推理模式

勾选模型的推理能力后，根据供应商实际支持的参数选择配置模式。

| 模式 | 如何配置 | Kilo 中的选择 |
| --- | --- | --- |
| 推理强度分级 | 勾选所需强度，或在 JSON 中自定义档位与参数 | 原生“默认”及启用的强度档位 |
| 模型默认配置（开关思考模式） | 选择协议并点击“填入协议模板”，核对默认开启和关闭参数 | “默认／关闭” |

**推理强度分级**适合支持 `reasoningEffort` 等强度参数的模型。比如勾选 `low` 会生成 `{"low":{"reasoningEffort":"low"}}`。点击 **仅保留默认档位** 会禁用其他已配置档位；“默认”本身不附加档位参数。

**开关思考模式**将默认开启参数写入模型 `options`，将关闭参数写入“关闭”档位。内置 `thinking.type`、`enable_thinking`、`chat_template_args.enable_thinking` 和 Anthropic 思考预算模板，均可自行调整。模板必须与上游协议匹配；供应商不支持关闭思考时，工具箱不能强制关闭。

保存推理模式会替换模型级的思考控制字段，并保留 `temperature` 等其他参数；切回分级模式会清除模型级开关参数。供应商级参数保持原样。**取消推理能力勾选只改变能力声明，不等于关闭思考，也不会清除已有推理请求参数。**

Kilo 7.8.1 / 7.8.3 原版在没有推理档位时会隐藏推理选择器。要让这种情况下仍能选择原生“默认”，请应用下述原生保存修复。

## 模型分组与原生保存修复

点击页面顶部 **分组与保存修复** 打开设置，按需调整：

| 设置 | 作用 | 默认值 |
| --- | --- | --- |
| `kiloPicker.hideGateway` | 隐藏 Kilo Gateway 模型，包括推荐、收藏和搜索结果中的对应项 | 开启 |
| `kiloPicker.disableMostUsed` | 取消“最常用”分组，模型保留在原供应商分组 | 开启 |
| `kiloPicker.fixNativeSave` | 修复原生模型保存，并在无推理档位时保留“默认”选项 | 开启 |
| `kiloPicker.autoApply` | 启动、设置变化或 Kilo 更新后自动尝试应用 | 关闭 |

设置开关不会在默认状态下自动修改安装文件。调整后，按 `Ctrl+Shift+P` 运行 **Kilo模型分组：应用补丁**，再按提示重新加载窗口。也可以开启自动应用；文件发生修改后仍需要重新加载。

这些功能通过本地补丁修改 Kilo 的界面文件。**Kilo 更新后不再仅因版本号未收录而停止应用**：

- **已收录版本**（7.8.1 / 7.8.3 Windows x64）：使用已验证的原版文件校验值，继续兼容已有备份和补丁。
- **未收录版本**：检查两个界面文件的模型来源、最常用分组、保存消息和默认推理选择器是否符合已支持的结构，并检查修改后代码的语法。检查通过后保存修改前文件与 SHA-256 记录，再应用补丁。
- **结构变化、定位不唯一或备份校验失败**：停止应用并说明原因；两个文件都检查通过后才开始写入，写入失败会尝试回滚。

开启 `kiloPicker.autoApply` 后，启动或检测到 Kilo 更新时会自动走上述流程。修改文件后仍需重新加载窗口。如果自动应用关闭，可手动运行 **Kilo模型分组：应用补丁**。运行 **Kilo模型分组：查看状态** 可以查看采用的是文件校验还是结构检查。

未收录版本的备份是首次检查时的本地文件基线，不代表已核验其官方来源，也不等于完成了该版本的全部运行测试。基线记录建立后，无法识别的额外修改会阻止覆盖；有工具箱补丁标记但缺少有效备份时也会停止。版本变化会建立独立基线，旧版本备份继续保留。不要手动删除工具箱的备份记录。

供应商和模型配置编辑不依赖这些补丁。

查看当前状态可运行 **Kilo模型分组：查看状态**。撤销补丁可运行 **Kilo模型分组：恢复原版并关闭自动应用**，再重新加载窗口。如果卸载工具箱时也想移除补丁，请先执行恢复原版。

## 备份与恢复

每次保存、导入或恢复配置前，工具箱都会在配置文件旁生成 `kilo.jsonc.bak-时间戳-随机值`（或 `kilo.json.bak-…`）备份。备份不会自动清理。

点击顶部 **恢复配置备份**，选择备份文件并确认，即可恢复。**此操作替换整个 Kilo 配置，包括所有供应商、模型和其他设置**；恢复前的当前配置也会先备份。

“恢复配置备份”恢复的是配置文件；“恢复原版并关闭自动应用”恢复的是 Kilo 安装文件，两者相互独立。

如果配置已被其他程序修改，工具箱会拒绝覆盖。请先处理未保存内容，再清空修改并刷新后继续。配置支持 JSON/JSONC，保留未编辑的属性；修改字段内部的注释可能随字段重写。

## 网络与凭据

只有点击 **读取模型** 时，工具箱才会请求供应商的 `/models` 列表接口，不调用聊天或生成接口。支持 OpenAI 与 Anthropic 列表格式、Anthropic 分页，并使用所配置的 API Key、环境变量或 Kilo 已保存的 API 凭据。

本地、私网和已识别的中国供应商接口直连。其他地址优先使用已监听的 `http://127.0.0.1:7897` 代理；代理不可用或出现网络故障时尝试直连。代理仅用于该请求，不修改系统设置；请求保留 TLS 校验，设有超时，最多读取 2000 个模型。

新填写的 API Key 会保存到本地 Kilo 配置中，配置备份也可能包含凭据。请将这些文件保留在本地，不要提交到公开仓库。本仓库与安装包不包含个人配置或密钥。

## 开发

```sh
npm ci
npm test
npm run package
```

打包后生成 `.vsix` 文件。测试覆盖配置编辑、管理页面交互、供应商模型读取、补丁应用与恢复等流程。补丁集成测试需要本机存在 `signatures.json` 所匹配的 Kilo 7.8.1 / 7.8.3 原版文件或已知原版备份，默认测试 7.8.3，也可用 `KILO_TEST_DIST` 指定目录、`KILO_TEST_VERSION` 指定受支持的版本；缺少测试资源时会明确跳过。
