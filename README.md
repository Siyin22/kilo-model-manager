# Kilo 模型工具箱

一个 VS Code 扩展，统一管理 Kilo 自定义模型、图片能力、推理档位、模型分组和原生保存修复。模型管理直接读写 Kilo 配置；分组和保存修复通过经过校验的本地补丁修改 Kilo 安装文件。不需要 Python，不调用模型 API。

## 从两个插件合并升级

0.2.0 已整合 kilo-picker-helper 0.1.1 的全部功能。安装标识继续使用 `local-tools.kilo-model-manager-local`，可直接升级原模型管理插件。卸载或禁用旧的 `local-tools.kilo-picker-helper` 并重新加载窗口后，仅需保留本工具箱。旧助手仍启用时，工具箱不会重复注册补丁命令或自动写入。

保留 `kiloModelManager.configPath`、全部 `kiloPicker.*` 设置及原命令。能够从旧助手存储目录接管 SHA-256 校验通过的原版备份；首次应用或恢复会将备份保存到工具箱自己的全局存储目录。已应用的旧补丁无需先恢复。请在接管前保留旧助手的存储目录。

管理页面顶部的“分组与保存修复”可打开统一设置，分别控制隐藏 Gateway、取消最常用分组、修复原生保存。默认不自动写入 Kilo 安装文件；可开启 `kiloPicker.autoApply` 或执行“应用补丁”。修复适配 Kilo 7.8.1 Windows x64，未知版本或未知文件修改会停止，不影响独立模型编辑功能。

原生保存修复解决已有推理档位等界面 Proxy 对象无法通过消息通道发送的问题，保留模型配置，并在发送失败时恢复按钮、显示错误。“恢复原版并关闭自动应用”会恢复两个 Kilo 界面文件，也会移除保存修复；它与“恢复配置备份”是不同操作。卸载工具箱前若需要移除补丁，请先执行恢复原版。

## 使用

1. 从仓库的 [Releases](https://github.com/Siyin22/kilo-model-manager/releases/latest) 下载 `.vsix`，然后在 VS Code 扩展面板菜单选择 **从 VSIX 安装**。
2. 按 `Ctrl+Shift+P`，运行 **Kilo 模型与推理设置**。
3. 选择提供商，点击已有模型或“添加模型”。
4. 编辑名称、推理/图片能力，勾选档位或修改参数 JSON。
5. 核对页面中的修改前后预览，点击“确认并保存”，再确认弹窗。

如果 Kilo 未自动刷新，使用页面顶部“重新加载窗口”。这会重新加载当前 VS Code 窗口，因此操作前结束正在运行的任务。

## 换电脑

登录 GitHub 下载 Release 附件中的安装包即可，不需要安装 Node.js 或 Python。安装 Kilo 后，先在 Kilo 配置自己的提供商和 API 凭据，再安装本扩展。按 `Ctrl+Shift+P` 打开本扩展的管理页面。

本仓库只备份插件源码和安装包，**不包含个人模型配置、API Key 或配置备份**。如果要迁移原电脑的模型列表，请自行安全迁移 Kilo 配置；该文件可能包含凭据，不要提交到仓库。

## 配置位置和兼容性

默认读取 `~/.config/kilo/kilo.jsonc`，不存在时读取同目录的 `kilo.json`。其他路径可通过 VS Code 设置 **kiloModelManager.configPath** 指定；更改后关闭管理页面，再重新打开。

目前管理已有提供商的模型。请先在 Kilo 配置提供商及 API 凭据。本扩展不会把提供商密钥传入编辑页面。

模型 ID 在编辑时只读；若需改 ID，请添加新模型后删除旧模型。配置的其他模型属性会保留。JSONC 支持注释、尾逗号；修改字段内部的注释可能随该字段重写，其余注释尽量由 JSONC 编辑器保留。拒绝重复键和无效配置。

独立安装的扩展不会因 Kilo 升级或重装而被覆盖。但如果 Kilo 将来改变配置格式，需要相应适配；重装整个 VS Code 用户环境会影响已安装扩展。

## 推理参数

勾选 `low` 生成 `{"low":{"reasoningEffort":"low"}}`。也可以自定义名称和参数，例如 `{"关闭":{"thinking":{"type":"disabled"}}}`。

点击 **使用模型默认设置** 会禁用已配置的档位，不通过档位附加 `reasoningEffort`、`thinking` 等参数。是否开启思考由模型和上游默认行为决定，不强制开启或关闭。提供商或模型 `options` 中已有的参数保持不变。

常用勾选项不再包含 `none`；高级 JSON 仍允许手动配置，已有自定义 `none` 不会被自动删除。扩展不验证模型支持情况。

保存时禁用未选择的常见档位及原有档位，保留被禁用的已有参数。取消“模型具备推理能力”是改变 Kilo 能力声明，不是命令模型关闭思考。未来 Kilo 新增默认档位时，可用自定义 JSON 将其 `disabled` 设为 `true`。

## 备份与恢复

每次保存自动生成相邻 `kilo.jsonc.bak-时间戳-随机值` 文件。配置在页面打开后被其他程序修改时拒绝覆盖，需要先撤销未保存修改并刷新。

“恢复备份”会恢复**整个配置文件**，包括所有提供商等设置；恢复前也会备份当前文件。备份可能包含凭据，请保留在本地。备份不自动清理。

## 开发与测试

```sh
npm install
npm test
npm run package
```

测试覆盖配置编辑、管理页面、原生保存消息、补丁开关组合、旧助手备份迁移、恢复及失败回滚。补丁集成测试需本机存在经过 `signatures.json` 校验的 Kilo 7.8.1 原版或 `.bak-model-picker-*` 备份，也可用 `KILO_TEST_DIST` 指定目录；缺少原版时明确跳过。源码仓库不包含 Kilo 的原版文件。
