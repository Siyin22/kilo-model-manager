# Kilo 模型与推理设置

独立的 VS Code 扩展，在一个页面中添加、编辑、删除 Kilo 自定义模型及其推理档位。直接读写 Kilo 配置，不修改 Kilo 扩展安装文件，不需要 Python，不调用模型 API。

## 使用

1. 从仓库的 [Releases](https://github.com/Siyin22/kilo-model-manager/releases/latest) 下载 `.vsix`，然后在 VS Code 扩展面板菜单选择 **从 VSIX 安装**。
2. 按 `Ctrl+Shift+P`，运行 **Kilo 模型与推理设置**。
3. 选择提供商，点击已有模型或“添加模型”。
4. 编辑名称、推理/图片能力，勾选档位或修改参数 JSON。
5. 核对页面中的修改前后预览，点击“确认并保存”，再确认弹窗。

如果 Kilo 未自动刷新，使用页面顶部“重新加载窗口”。这会重新加载当前 VS Code 窗口，因此操作前结束正在运行的任务。

## 换电脑

登录 GitHub 下载 Release 附件中的安装包即可，不需要安装 Node.js 或 Python。安装 Kilo 后，先在 Kilo 配置自己的提供商和 API 凭据，再安装本扩展。按 `Ctrl+Shift+P` 打开本扩展的管理页面。

本仓库只备份插件源码和安装包，**不包含个人模型配置、API Key 或配置备份**。如果要迁移原电脑的模型列表，请自行安全迁移 Kilo 配置；该文件可能包含凭据，不要提交到仓库。

## 配置位置和兼容性

默认读取 `~/.config/kilo/kilo.jsonc`，不存在时读取同目录的 `kilo.json`。其他路径可通过 VS Code 设置 **kiloModelManager.configPath** 指定；更改后关闭管理页面，再重新打开。

目前管理已有提供商的模型。请先在 Kilo 配置提供商及 API 凭据。本扩展不会把提供商密钥传入编辑页面。

模型 ID 在编辑时只读；若需改 ID，请添加新模型后删除旧模型。配置的其他模型属性会保留。JSONC 支持注释、尾逗号；修改字段内部的注释可能随该字段重写，其余注释尽量由 JSONC 编辑器保留。拒绝重复键和无效配置。

独立安装的扩展不会因 Kilo 升级或重装而被覆盖。但如果 Kilo 将来改变配置格式，需要相应适配；重装整个 VS Code 用户环境会影响已安装扩展。

## 推理参数

勾选 `low` 生成 `{"low":{"reasoningEffort":"low"}}`。也可以自定义名称和参数，例如 `{"关闭":{"thinking":{"type":"disabled"}}}`。

思考开关模板使用 `on → reasoningEffort: high`、`off → reasoningEffort: none`。这不是通用的原生开关协议：AxonHub 普通 OpenAI 出口和实际模型上游可能需要额外转换。此扩展不验证模型支持情况，不承诺这些参数一定会生效。

保存时禁用未选择的常见档位及原有档位，保留被禁用的已有参数。取消“支持推理”是改变 Kilo 能力声明，不是命令模型关闭思考。未来 Kilo 新增默认档位时，可用自定义 JSON 将其 `disabled` 设为 `true`。

## 备份与恢复

每次保存自动生成相邻 `kilo.jsonc.bak-时间戳-随机值` 文件。配置在页面打开后被其他程序修改时拒绝覆盖，需要先撤销未保存修改并刷新。

“恢复备份”会恢复**整个配置文件**，包括所有提供商等设置；恢复前也会备份当前文件。备份可能包含凭据，请保留在本地。备份不自动清理。

## 开发与测试

```sh
npm install
npm test
npm run package
```

不依赖之前针对 Kilo 7.7.9 的本地保存补丁。原生 Kilo 页面仍由 Kilo 自身负责；本扩展的编辑入口是独立页面。
